## **1. Roles → should be ENUM, not VARCHAR**

Right now:

```sql
role VARCHAR(50)
```

👉 Upgrade:

```sql
CREATE TYPE member_role AS ENUM ('admin', 'member', 'viewer');
```

Why:

* prevents invalid roles
* cleaner validation
* stronger schema signal

---

## **2. Missing composite index (important)**

You’ll often query:

> tasks in a project by status

Add this:

```sql
CREATE INDEX idx_tasks_project_status 
ON tasks(project_id, status);
```

This matters for Kanban performance.

---

## **3. Workspace membership layer (optional but powerful)**

Right now access is:

> org → project

But real SaaS often has:

> org → workspace → project

👉 Add (optional but elite):

```sql
workspace_members
- workspace_id
- user_id
- role
```

This gives:

* team-level isolation inside org
* closer to Jira/Notion behavior

---

## **4. Soft deletes (important in real systems)**

Right now everything is hard delete.

👉 Add:

```sql
deleted_at TIMESTAMPTZ
```

to:

* projects
* tasks

Why:

* recovery
* audit
* production realism

Schema reference:
- users (id, name, email, password_hash, avatar_url)

Build these routes:
POST /api/auth/signup
POST /api/auth/login
POST /api/auth/refresh
POST /api/auth/logout

Auth flow:
- Signup → hash password (bcrypt, 10 rounds) → create user 
  → create org with slug → add user as admin member 
  → return access + refresh tokens
- Login → verify password → return both tokens
- Access token: JWT, expires 15min
- Refresh token: random UUID stored as hash in DB, expires 7d
- Refresh route: verify token hash → revoke old → issue new pair
- Logout: revoke refresh token in DB

Middleware to build:
- authenticate.js: verify JWT, attach req.user
- All protected routes use this middleware

Rules:
- Passwords never returned in responses
- Token hash stored (never raw token)
- Refresh token rotation (revoke on use)
- Proper HTTP codes: 201, 200, 401, 409, 422
